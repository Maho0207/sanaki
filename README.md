# 早菜島軌道(さなじまきどう)公式サイト

架空の鉄道「早菜島軌道」の公式サイトです。サーバー不要の静的サイトなので、GitHub Pages でそのまま公開できます。

## できること

| ページ | 内容 |
|---|---|
| 運行情報(トップ) | 9路線の運行状況、路線図に走行中の列車をリアルタイム表示 |
| 列車位置 | 路線ごとの縦型路線図に下り・上りの列車を表示(15秒ごと更新) |
| 時刻表 | 駅ごとの方面別時刻表、まもなく発車、列車ごとの停車駅と現在地 |
| 乗換案内 | 出発/到着時刻指定の経路検索(見合わせ区間・運休列車は自動で除外) |
| 特急予約 | 区間ごとに座席を指定して予約、予約の確認・取消(空席はスプレッドシートで管理) |
| 車両・運用 | 今日どの編成がどの運用・列車に入っているか、編成不足の確認 |
| 管理・テスト | 時刻シミュレーション、見合わせの手動発生、編成の編集と書き出し |

時刻はすべて日本時間で、3:00 を境に1日の運行が切り替わります。

## GitHub Pages で公開する

1. このフォルダの中身をそのまま GitHub リポジトリに push します(`index.html` がリポジトリ直下に来るように)。
2. リポジトリの **Settings → Pages** で、Source を「Deploy from a branch」、Branch を `main` / `(root)` にして保存します。
3. 数分後に `https://<ユーザー名>.github.io/<リポジトリ名>/` で表示されます。

### パソコンで確認する(ローカル)
`index.html` をダブルクリックで開くと、ブラウザの安全上の制限(file:// からはデータの読み込みや JavaScript モジュールが禁止される)で表示されません。次のどれかで開いてください。

- Windows: `start-windows.bat` をダブルクリック / Mac: `start-mac.command` をダブルクリック(どちらも Python 3 が必要。初回の Mac は右クリック→「開く」)
- このフォルダで `python3 -m http.server 8000` を実行し、`http://localhost:8000` を開く
- VS Code の拡張機能「Live Server」で開く

## 編成の登録(編成が足りないと運休)

ダイヤは 670 の運用(特急車 T 58・一般車4両 B 584・一般車2両 C 27・機関車列車 L 1)で組まれています。
登録された編成を毎日ローテーションで各運用に割り当て、**割り当てられなかった運用の列車は運休**になります(2編成併結の列車は片方が欠けると減車で運転)。

登録方法は2通りあります。

- **リポジトリで管理**: `data/formations.json` を編集して push。
- **スプレッドシートで管理**(予約用スプレッドシートを設定した場合): 「編成」シートに1行でも登録があると、そちらが優先されます。管理ページの「スプレッドシート用にコピー」で今の一覧を貼り付けられます。

### 製造年・自動離脱
各編成に `built`(製造年)を登録できます(JSON・スプレッドシート「編成」シートの「製造年」列・管理ページ)。車両・運用ページに製造年と車齢、次回の検査日を表示します。

`data/sim.json` の `withdrawal` の設定で、編成が自動的に運用を離れます。

| 種類 | 既定値 | 内容 |
|---|---|---|
| 定期検査 | 120日ごとに2日間 | 編成ごとに時期をずらして入場 |
| 全般検査 | 4年(1460日)ごとに21日間 | 同上 |
| 事故・故障 | 1日あたり0.03%×(1+車齢×4%) | 5〜60日の長期離脱。古い編成ほど起きやすい |

日付と編成番号から決まる計算なので、誰が見ても同じ結果になります。離脱した編成のかわりに予備編成が入り、予備が足りない運用は運休になります(初期データには予備として特急車6・一般車4両40・2両4・機関車1編成を含みます。予備を減らすと運休が起きやすくなります)。手動で長期離脱させるときは、状態を「検査」「休車」「廃車」にしてください。

各項目: `id`(編成番号) / `type`(T・B・C・L) / `series`(形式。特急車は `seatmaps.json` の形式名と同じにする。例 `4000型`) / `cars`(両数) / `status`(在籍・検査・休車・廃車。在籍以外は運用に入りません) / `built`(製造年) / `pin`(固定したい運用番号。例 `T005`) / `note`。

一般車4両の運用が足りないときは、余っている2両編成(C)を2本つないで代走させます(`js/config.js` の `allowDoubleTwoCar` で切替)。2両編成の運用を先に埋め、残った2両編成を2本ずつ4両運用に回し、それでも足りない運用が運休になります。車両・運用ページでは「9001F+9002F」のように表示されます。

初期データは全運用ぶんの編成が登録されています(2両編成の余りは0本なので、代走を使うには2両編成を追加登録してください)。運休を試すには編成を削除するか、状態を「検査」にしてください。

## 運転見合わせ

### ランダム発生
`data/sim.json` の `randomIncident` で設定します。既定は「1路線・1時間あたり2%」。日付と路線から決まる乱数なので、**全員に同じ見合わせが同時に表示**されます(発生時刻になるまでは表示されません)。見合わせ中は区間内の列車が止まり、再開後はその分遅れて走ります。乗換案内は見合わせ区間を避けて検索します。

### 手動発生
次のどちらかに追加します。

- `data/incidents.json`
  ```json
  [
    {"date": "2026-11-22", "line": 2, "from": "増森", "to": "磯浜", "start": "08:10", "end": "09:30", "reason": "車両点検"}
  ]
  ```
  `date` を省略すると毎日、`end` を空にすると「再開見込み未定」になります。
- スプレッドシートの「運行情報」シート(push 不要で即時反映。サイトを再読み込みすると表示されます)。

管理ページ(フッターの「管理・テスト」)では、自分のブラウザだけで見合わせを起こして動作を確認したり、公開用の JSON・シート用の行をコピーしたりできます。

## 特急予約(Google スプレッドシート連携)

予約画面・予約票・乗換案内には「架空の鉄道で、料金は請求されない」旨を表示しています。

`gasUrl` が空のあいだは、予約がそのブラウザ内だけに保存される「デモモード」で動きます。全員で空席を共有するには:

1. 新しい Google スプレッドシートを作成し、**拡張機能 → Apps Script** を開きます。
2. `gas/Code.gs` の内容を貼り付けて保存し、関数 `setup` を実行します(初回は権限を承認)。
   「予約」「空席状況」「販売停止」「編成」「運行情報」シートが作られます。
3. **デプロイ → 新しいデプロイ → ウェブアプリ**。実行ユーザー「自分」、アクセスできるユーザー「全員」でデプロイします。
4. 表示された `https://script.google.com/macros/s/…/exec` を `js/config.js` の `gasUrl` に貼り付けて push します。
5. `Code.gs` 先頭の `SITE_URL` に公開サイトの URL(例 `https://yourname.github.io/sanajima/`)を入れて保存し、関数 `installTrigger` を実行します。以後1時間ごとに次のシートが自動更新されます。
   - **離脱情報**: 検査・事故・手動(状態)で離脱中の編成。復帰すると「復帰済」になります
   - **見合わせ記録**: 発生したランダム見合わせと、手動の見合わせ(`data/incidents.json`・「運行情報」シート)

   Apps Script はサイトと同じ `data/sim.json` を読んで同じ計算をするので、サイトの表示とシートの記録は一致します(計算部分は `js/sim.js` と `Code.gs` の末尾に同じものが入っています)。

スプレッドシートでの操作:

- **予約**: 1座席1行の台帳。「状態」を `取消` にすると空席に戻ります。
- **空席状況**: 乗車日・列車ごとの予約席数(左)と、乗車日・列車・座席種別(普通席/特別席/展望席/個室)ごとの予約数(右)を自動集計します。
- **販売停止**: 乗車日(空欄なら毎日)と列車番号を書くと、その列車の予約を止めます。

予約名は自由入力(ニックネーム可・16文字まで)で、予約番号と予約名で確認・取消できます。サイトの予約画面では、列車ごと・号車ごとに座席種別別の空席(◎○△×と残り席数)を表示します。

座席は区間ごとに管理しているので、早菜中央→大浜の座席を、大浜→端浜で別の人が予約できます。座席数・予約可能日数は `js/config.js` で変更できます。

## 運賃・特急料金

- `data/fare.csv` … 運賃表(`キロ数,新運賃,現行運賃`。2列目の「新運賃」を使用)
- `data/limited_express_fee.csv` … 特急料金表(`~まで,料金`)

どちらも1km未満の端数は切り上げ、表の最大キロを超えるときは最終行の金額です。乗換案内では、運賃は全区間の通算キロ、特急料金は特急に乗る区間ごとに計算します。表を差し替えるときは同じ形式のCSVで上書きしてください。

営業キロは `data/distances.json`(`tools/kilometers.xlsx` の各駅のキロ程から作成)を使っています。

## 特急車両と座席配列

特急車は8形式(1000型・1500型 Mountain Express / 2000型 Ocean Express / 3000型 Island Express / 4000型 Cherry Express / 5000型・5500型 Air Express / 6000型 Premium Express)です。座席配列は `data/seatmaps.json`(`tools/seatmaps.xlsx` から作成)で、予約画面には列車に当日入る編成の形式の座席表が出ます。

- **特別席**(各形式の特別席車・5000型 First Class): 特急料金 + 500円
- **展望席**: 追加料金なし(座席表で色分け)
- **個室**: 1室単位で予約。料金 = 特急料金 × 利用人数 + 個室料金(座席配列表の金額)。6000型の展望個室(8人用)も同様

形式ごとに優先して入る路線は `js/config.js` の `seriesPreference` で設定します(初期値: 5000型・5500型→空港線、4000型→桜川線、3000型→早菜離島線、2000型→東部・西部海岸線、1000型・1500型→山岳線・東越線・天連峡谷線)。特急の運用は複数の路線をまたぐため、あくまで「優先」です。4000型・5000型は6両編成で、4両編成と共通運用です。

初期の編成は 1001F〜(1000型)… 6001F〜(6000型)の計58編成、一般車は 7001F〜(7000系 4両)・9001F〜(9000系 2両)です。

> 予約は「列車番号・号車・座席番号」で管理します。編成の登録を変えて形式が変わると、既存の予約の座席番号が新しい形式に無い場合があります。

## ダイヤを更新する

Excel のダイヤを作り直したときは、次のコマンドで JSON を作り直します(Python 3 と openpyxl が必要)。

```bash
pip install openpyxl
python3 tools/build_data.py tools/diagram.xlsx
```

`data/network.json`(路線・駅・列車)と `data/operations.json`(運用)が更新されます。変換時に、全列車の始発・行先が Excel の「始発」「行先」欄と一致するかを検査し、一致しない列車があれば一覧を表示します(併結区間が路線をまたぐ場合や、途中駅で列車番号が変わる直通も自動でつなぎます)。キロ程・座席配列・既定の編成は次で作り直せます(`--formations` を付けると formations.json を初期状態に戻します)。

```bash
python3 tools/build_extra.py --km tools/kilometers.xlsx --seats tools/seatmaps.xlsx
````data/formations.json` は既にあれば上書きしません。

路線図の形は `js/ui.js` の `ANCHORS`(主要駅の座標)で調整できます。お知らせは `data/news.json` を編集してください。

data/               ダイヤ・運用・編成・キロ程・座席配列・運賃表・見合わせ・お知らせ
gas/Code.gs         予約用 Google Apps Script
tools/build_data.py  ダイヤ Excel → JSON 変換
tools/build_extra.py キロ程・座席配列 Excel → JSON 変換
```
